# 综合实验详细需求与三人分工

## 0. 文档目的

本文说明综合实验的完整需求。  
本文给出 A、B、C 三名组员的分工建议。  
A、B、C 是角色代号，不绑定具体姓名。  
分工按模块和接口划分，减少交叉修改。  
每名组员可以使用 agent 独立开发自己的模块。  
未确定的内容用【待确认】标记。

使用方式：

1. 全组先填写【待确认】项。
2. 冻结接口后再开始编码。
3. 每周对照里程碑检查进度。
4. 每个阶段完成后打 Git tag。
5. 接口变化必须更新本文档。

本文按 ASD-STE100 原则编写：

- 使用短句。
- 每句只表达一个动作或一个事实。
- 使用主动语态。
- 术语首次出现时定义，此后保持一致。
- 需求和接口使用表格。

## 1. 项目目标

综合实验要求实现一个完整的计算机系统。  
系统运行在 ThinPAD-Cloud 实验平台。  
CPU 采用五级流水线。  
CPU 支持监控程序基本版本使用的 RV32I 指令。  
CPU 支持小组指定的 3 条 RISC-V B 扩展指令。  
B 扩展编码按 0.92 版本。  
CPU 通过 Wishbone 访问 SRAM 和 UART。  
系统能够运行监控程序 Ver.1。  
系统能够运行监控程序自带测例。  
提高要求是中断异常和虚拟内存。  
中断异常对应监控程序 Ver.2。  
虚拟内存对应监控程序 Ver.3。

## 3. 功能需求

### 3.1 CPU 与流水线

CPU 必须采用五级流水线：

| 阶段 | 名称 | 主要工作 |
|---|---|---|
| IF | 取指 | 根据 PC 读取指令 |
| ID | 译码 | 译码、读寄存器、生成立即数 |
| EXE | 执行 | ALU 运算、地址计算、分支比较 |
| MEM | 访存 | 读写 SRAM/UART |
| WB | 写回 | 写通用寄存器或 CSR |

必须实现：

- 32 位数据通路。
- 32 位 PC。
- 32×32 通用寄存器堆。
- RV32I 指令译码。
- 3 条指定 B 扩展指令。
- 流水线寄存器。
- 数据前传。
- load-use 暂停。
- 分支冲刷。
- IF 和 MEM 两个 Wishbone Master。
- IF/MEM 总线仲裁。
- 精确异常所需的流水线标记和冲刷。

数据冲突要求：

- ALU 结果可以前传到 EXE。
- load 结果可以前传到 EXE。
- load-use 必须插入气泡。
- CSR 读写位置必须明确。
- CSR RAW 冲突必须处理。

控制冲突要求：

- 分支可以在 ID 或 EXE 处理。
- 分支成立时必须冲刷错误路径指令。
- 跳转目标必须正确。
- 分支处理阶段必须写入报告。

结构冲突要求：

- IF 和 MEM 不能同时驱动同一条总线。
- 必须使用仲裁器。
- 未选中 Master 必须保持请求。
- ACK 必须送回发起请求的 Master。

### 3.2 总线与 SoC

必须实现：

- Wishbone Master。
- Wishbone 仲裁器。
- `wb_mux` 地址选择。
- BaseRAM 控制器。
- ExtRAM 控制器。
- UART 控制器。
- 板级顶层。
- 时钟和复位。
- 地址映射。

地址映射：

| 外设 | 起始地址 | 结束地址 |
|---|---|---|
| BaseRAM | `0x8000_0000` | `0x803F_FFFF` |
| ExtRAM | `0x8040_0000` | `0x807F_FFFF` |
| UART | `0x1000_0000` | `0x1000_FFFF` |

UART 要求：

- 数据寄存器 `0x1000_0000`。
- 状态寄存器 `0x1000_0005`。
- 状态 bit5 为发送就绪。
- 支持轮询发送。
- P1 支持接收中断。

板级要求：

- 使用 `rv-2025` 的板级约束和 PLL。
- 顶层模块名称按 2026 工程要求确定。
- 保留单步时钟按钮调试能力。
- 保留 LED 或数码管调试输出。

### 3.3 监控程序

必须支持三个版本：

| 版本 | 功能 |
|---|---|
| Ver.1 | 基本启动、加载、运行、串口命令、测例 |
| Ver.2 | 增加 CSR、异常、中断、UART 中断 |
| Ver.3 | 增加 Sv32 页表和虚拟内存 |

监控程序要求：

- 能从 BaseRAM 启动。
- 能通过 UART 接收命令。
- 能加载用户程序。
- 能运行用户程序。
- 能运行自带测例。
- 能显示异常和中断信息。
- Ver.2 能处理 UART 中断。
- Ver.3 能进行地址翻译和缺页处理。

必须取得以下材料：

- 监控程序文档。
- Ver.1/2/3 二进制或源码。
- 自带测例。
- 性能测例，例如 3CCT、4MDCT。
- 监控程序加载地址和内存布局。

### 3.4 中断与异常

P1 要求实现：

- CSR 寄存器。
- CSR 读写指令：`csrrw`、`csrrs`、`csrrc`、`csrrwi`、`csrrsi`、`csrrci`。
- 精确异常。
- 异常入口。
- `mret` 返回。
- `ecall`。
- 非法指令异常。
- UART 中断。
- `mtime` 和 `mtimecmp`。
- 中断屏蔽和优先级。

CSR 至少包括：

- `mstatus`
- `mtvec`
- `mip`
- `mie`
- `mscratch`
- `mepc`
- `mcause`
- `mtval`（按需）
- `satp`（P2）
- `pmpcfg0`、`pmpaddr0`（可忽略功能，但不能异常）

实现要求：

- CSR 地址空间按稀疏方式实现。
- 处理 CSR 读写权限。
- 处理 WARL 字段。
- 异常发生时，后续指令不得产生副作用。
- 跳转、写内存、写 CSR、写寄存器必须按异常精度处理。
- `mtime`/`mtimecmp` 通过 load/store 访问。
- 可以实现为独立 Wishbone Slave。
- 也可以在 MEM 段特判。
- 来自 M 态的时钟中断应按监控程序逻辑过滤。
- 必须能判断异常发生时的特权态。

### 3.5 虚拟内存

P2 要求实现：

- `satp` 寄存器。
- Sv32 两级页表。
- 页表遍历状态机。
- 虚拟地址到物理地址翻译。
- 页表项权限检查。
- 缺页异常。
- IF 和 MEM 的地址翻译。
- 页表修改后的刷新机制。

实现要求：

- 34 位物理地址可以去掉最高 2 位，当作 32 位地址使用。
- 不需要实现 RSW、D、A、G 位。
- 不需要实现完整 MMU 异常恢复。
- 需要支持监控程序 Ver.3 的 G 命令虚拟地址。
- 用户程序放在物理地址 `0x80100000`。
- G 命令指定虚拟地址 `0x0` 时，用户程序应能运行。
- 建议把 MMU 做成独立模块。
- MMU 接在 CPU 访存请求和 Wishbone 仲裁器之间。
- 这样 A、B、C 的修改范围清晰。

### 3.6 可选扩展

可选扩展不阻塞 P0、P1、P2。

性能类：

- 分支预测。
- 指令 Cache。
- 数据 Cache。
- TLB。
- 更多流水段。
- 提高主频。

外设类：

- VGA。
- Flash。
- GPIO。

功能类：

- 更多异常和中断。
- PMP。
- S 态。
- uCore。
- M/F/A 扩展。

可选扩展要求：

- 能展示功能。
- 有性能数据对比。
- 保留未实现功能的版本。
- 使用 Git tag 保存基线。
- 实现 Cache/TLB 时注意 `FENCE.I` 和 `SFENCE.VMA`。
- 清空顺序应先 dcache，再 icache 和 TLB。

## 4. 接口与模块边界

### 4.1 目录所有权

建议目录：

```text
rtl/
  core/        A 负责
  soc/         B 负责
  priv/        C 负责
  include/     共享接口和类型
sim/
  core/        A 负责
  soc/         B 负责
  priv/        C 负责
  integration/ B 负责
scripts/       B 负责
monitor/       B 负责
docs/          全组共享
```

规则：

- A 不修改 `rtl/soc/` 和 `rtl/priv/`。
- B 不修改 `rtl/core/` 和 `rtl/priv/` 的内部实现。
- C 不修改 `rtl/core/` 和 `rtl/soc/` 的内部实现。
- 接口变更必须先改 `rtl/include/` 或 `docs/interface/`。
- 接口变更必须通知另外两人。
- B 负责集成顶层。
- A 和 C 通过 PR 提交模块。
- B 负责合并到集成分支。

### 4.2 接口合同

#### CPU 与 SoC

`cpu_core` 向 B 提供：

| 信号 | 方向 | 说明 |
|---|---|---|
| `imem_req` | 输出 | 取指请求 |
| `imem_addr` | 输出 | 取指虚地址 |
| `imem_rdata` | 输入 | 指令数据 |
| `imem_ack` | 输入 | 取指完成 |
| `imem_fault` | 输入 | 取指异常 |
| `dmem_req` | 输出 | 数据请求 |
| `dmem_we` | 输出 | 写使能 |
| `dmem_addr` | 输出 | 数据虚地址 |
| `dmem_wdata` | 输出 | 写数据 |
| `dmem_sel` | 输出 | 字节使能 |
| `dmem_rdata` | 输入 | 读数据 |
| `dmem_ack` | 输入 | 访存完成 |
| `dmem_fault` | 输入 | 访存异常 |

B 负责把上述请求转换为 Wishbone 事务。

#### CPU 与 CSR/异常

C 向 A 提供：

| 信号 | 方向 | 说明 |
|---|---|---|
| `csr_addr` | 输入 | CSR 地址 |
| `csr_we` | 输入 | CSR 写使能 |
| `csr_wdata` | 输入 | CSR 写数据 |
| `csr_rdata` | 输出 | CSR 读数据 |
| `csr_valid` | 输出 | CSR 访问有效 |
| `trap_req` | 输出 | 异常或中断请求 |
| `trap_cause` | 输出 | 异常原因 |
| `trap_tval` | 输出 | 异常附加信息 |
| `trap_epc` | 输出 | 异常返回地址 |
| `trap_taken` | 输入 | 异常已接受 |
| `mret` | 输入 | 异常返回 |
| `priv_mode` | 输出 | 当前特权态 |
| `irq_uart` | 输入 | UART 中断 |

A 负责在流水线中传递异常标记。  
C 负责 CSR 和 trap 逻辑。  
B 负责把 UART 中断送到 C。

#### MMU 与总线

C 向 B 提供 MMU 接口：

| 信号 | 方向 | 说明 |
|---|---|---|
| `va` | 输入 | 虚拟地址 |
| `pa` | 输出 | 物理地址 |
| `req` | 输入 | 翻译请求 |
| `we` | 输入 | 访问类型 |
| `priv` | 输入 | 特权态 |
| `satp` | 输入 | 页表基址 |
| `fault` | 输出 | 缺页或权限异常 |
| `flush` | 输入 | 刷新 TLB |

B 负责把 MMU 接入总线。  
A 负责把虚地址和异常标记送到 MMU。  
C 负责页表遍历和权限检查。

#### 调试接口

A 向 B 和 C 提供：

| 信号 | 说明 |
|---|---|
| `dbg_pc` | 当前 PC |
| `dbg_inst` | 当前指令 |
| `dbg_state` | 流水线状态 |
| `dbg_commit_valid` | 指令提交有效 |
| `dbg_commit_pc` | 提交 PC |
| `dbg_commit_inst` | 提交指令 |
| `dbg_trap` | 异常提交 |

这些信号用于仿真、波形和报告。  
这些信号不参与综合逻辑。

## 10. 协作规则

### 10.1 Git

建议分支：

```text
complex/integration
feat/a-core
feat/b-soc
feat/c-priv
```

规则：

- A 只提交 `rtl/core/` 和 `sim/core/`。
- B 只提交 `rtl/soc/`、`sim/soc/`、`sim/integration/`、`scripts/`、`monitor/`。
- C 只提交 `rtl/priv/` 和 `sim/priv/`。
- 接口修改先提交 `rtl/include/` 或 `docs/interface/`。
- B 负责合并到 `complex/integration`。
- 合并前必须通过编译和单元测试。
- 每个里程碑打 tag。

### 10.2 Agent 协作

每名组员的 agent 必须：

- 先读接口文档。
- 先写单元测试。
- 使用 stub 独立验证。
- 不修改其他人的目录。
- 提交前运行本地测试。
- 在 `docs/handoff/` 写交接说明。

交接说明必须包含：

- 已完成内容。
- 未完成内容。
- 接口变化。
- 测试命令。
- 已知问题。
- 下一步建议。

### 10.3 集成

B 是集成负责人。  
A 和 C 提供模块和测试。  
B 负责顶层连接、监控程序、上板和 CI。  
集成失败时，先定位接口问题。  
不要直接在集成分支修改其他人的模块。  
先在自己的分支修复，再提交 PR。
